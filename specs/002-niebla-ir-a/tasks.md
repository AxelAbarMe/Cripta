## Dependencias y orden de ejecución

- Fase A precede a B; B precede a C; C precede a D; D precede a E; E precede al cierre de F.
- La suite de Parte I y la auditoría se ejecutan después de la integración. La prueba binaria de guardado y carga depende de 004, que posee el formato y hará el único cambio de versión.
- Las tareas de ruta y viaje que dependen del costo de salida en el movimiento de `partida.py` llevan **Depende de 001**. El punto de corte del Pull Request es completar las fases A a F, incluida la tarea T024 tras integrar 001; T040 depende de 004 para la codificación binaria. El Pull Request de esta capacidad no puede fusionarse antes del Pull Request de 001.
- Las pruebas preceden al código correspondiente. [P] identifica tareas independientes en archivos distintos; la lista está marcada en cada tarea.

## Estrategia de implementación

Primero completar Fase A y validar el dominio puro; continuar en orden por B, C y D. Fase E compara algoritmos y registra resultados medidos. El alcance mínimo revisable es Fases A–B: conocimiento observable, antorcha e integración lógica reversible. La funcionalidad de viaje requiere completar C–D. El cierre requiere conservar Parte I y revisar mediciones; el guardado binario depende de 004.
